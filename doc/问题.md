- **现状(2026-08-03)**:❌ 未做 —— 无 `createOrchestrator*`;plan-execute 仍靠 subagent 组合模拟(planner-demo)。设想详见 `doc/archive/roadmap.md` #12。

### #20 记忆分类型分层管理(低优先,搁置)
- **问题**:记忆是不是可以分类型、分层管理?例如:工具信息 / 系统提示词 / 用户输入 / AI 输出 / 错误信息;某条上下文是否压缩过;临时恢复的上下文是否需要压缩、何时卸载。
- **决策**:❓ 中等工程(改 AgentMessage 类型 + summarization + trimMemoryMessages)。当前压缩后原文不可恢复;要做「分层保留 + 压缩可恢复」涉及核心消息模型改动,**优先级低于修 bug / 文档**。
- **现状(2026-08-03)**:❌ 未做(符合搁置决策)—— summarization 无分层。

### #21 纯代码组件逃生舱 + code-writer skill(方向已定,零落地)
- **问题**:纯前端页面代码编写 agent 的设计实现 —— 只生成前端代码 html + js + css 内联完整页面。
- **决策**:🔄 原「整页 HTML 生成」**砍**,改为「**纯代码组件逃生舱 + code-writer skill**」:
  1. **customCode 作为页面 schema 第 13 种 module type**,与 heading/button 同构:`props.code`(内联 HTML+CSS+JS,自包含)。agent 用 `write` 整体写,继承 schema 校验 + 快照回退 + 拦截器。渲染 `<iframe srcdoc sandbox="allow-scripts">`(无 allow-same-origin 隔离 parent/cookie)。`interceptors.write` 静态危险调用扫描(`eval`/`document.cookie`/`window.parent`)。**SDK 永不 eval 用户代码**。
  2. **用 `code-writer` skill 注入规范,不用 subagent**(代码生成是「一次性产出字符串」,主 agent 直接写最省)。主体仍是结构化内置组件(90%),customCode 只占逃生舱(10%)。
  3. 强依赖模型能力(#15):systemPrompt 点明用强模型。
- **现状(2026-08-03)**:❌ 未做 —— complex-demo 无 customCode type、无 code-writer skill;方向已定(逃生舱),零落地。
