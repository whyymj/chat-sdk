# 应用前景评估 + 拓展方向规划(2026-08-03)

> 一问三答:前景是否广 → 壁垒在哪 → 往哪拓展。结论先行:**窄而深的利基,不往通用平台扩(稀释护城河),往「AI 安全操作数据的行业标准」这个定位打。**

## 1. 定位判断(诚实版)

不是通用 AI 平台(那条赛道被 langgraph/langchain 占死,也违背「自研轻量 + 规范化 JSON 操作」原则)。它在「**让 AI 安全地操作浏览器内运行时数据**」这个点是稀缺的。

| 场景 | 本 SDK 的角色 | 前景 |
|---|---|---|
| 低代码/页面构建器(专题页、落地页、活动页) | ✅ **核心** —— LLM 改页面配置 JSON,这正是设计初衷 | 大 |
| 内容运营/后台数据操作(表单、列表、批量) | ✅ 强 —— schema 校验 + 乐观锁 + 快照,安全边界是最大卖点 | 中 |
| 可视化编辑器(AI 与拖拽双通道) | ✅ 强 —— 同一份 bind,AI 改和手拖共享 | 中 |
| 通用聊天助手 | ❌ 不是 —— 无知识库/通用问答定位 | — |

**前景的短板**:依赖「AI 操作结构化数据」范式被接受。集成方只想做普通聊天框时价值不大;只有「AI 要改页面/数据」的场景才发光。**市场是垂直的,不是全量的。**

## 2. 护城河(真正的壁垒不是功能多,是这套安全链)

- **schema 自动白名单**:ZodObject 顶层声明 key 自动成为可读写白名单,未声明字段投影隐藏,子路径递归校验
- **乐观锁(expectedHash)+ 冲突人工介入**:外部/多 agent/用户改过 → 触发冲突挂起人工三选一
- **快照回退**:per-path 自动快照 + 一键 restore + checkpoint 整体回滚
- **per-path 范围收紧(strict)**:聚焦后越界写返回 PATH_DENIED

市面上「让 AI 直接改页面数据」大多是 LLM 输出 JSON 字符串强塞,不可控;本 SDK 把它变成**强约束的受控通道**。这是护城河,与 `doc/问题.md` 总原则一致。

## 3. 拓展方向(按「强化护城河 → 拓宽场景 → 生态」分档,优先级从高到低)

### A. 强化护城河(最该做,成本低、直接加深壁垒)

1. **focus-context(已规划 `2026-08-03-focus-context`)**:指定组件精修 + strict 范围收紧。把安全通道从「整页」细化到「单组件」—— 比 langchain 强得多的精细化控制,差异化卖点。
2. **code-writer skill + customCode 逃生舱(问题.md #21,方向已定零落地)**:内置组件做不到的特效,agent 生成自包含 HTML+CSS+JS(沙箱 iframe + 危险调用扫描)。补上「schema 强约束」和「自由代码」之间最后一环。
3. **交互回溯 / 操作审计可视化**:`onAudit` 已有结构化审计,缺「回放」——把 LLM 每步操作渲染成可视化轨迹(改了哪、改了啥、能回退到哪)。对信任安全链的集成方是强加分。

### B. 拓宽场景(让 SDK 出圈,依赖集成方/新能力)

4. **数据报表/可视化生成**:agent 读 bind 数据 → 生成图表配置 → 写回 → 宿主渲染。规范化 JSON 操作的自然延伸,比代码生成更贴合定位。
5. **跨页面/多步骤工作流**:focus + mission + automation 已覆盖单页长任务;跨页面状态迁移(serialize 当前 bind → 新页恢复)是下一台阶。
6. **服务端 Node Agent**(README 已提,可强化):headless + storage + 真 LLM,后端批处理/数据清洗。验证 SDK 不止浏览器。

### C. 生态(远期,现在别投入)

7. **组件/schema 市场**:共享 schema 定义 + 渲染组件,让「一个页面」能导出导入。等集成方数量起来再做,否则空转。
8. **模型中立 + 多云**:已兼容 OpenAI 协议,低成本跟进新模型即可,不是投入重点。

## 4. 建议(下一步)

最该做的三件事恰好都已规划或已定方向,三者都强化「可控性 + 可定制」这条主线:

| 方向 | 状态 | 价值 |
|---|---|---|
| focus-context(指定组件精修) | ✅ 已规划 | 单组件级安全收紧,差异化卖点 |
| code-writer 逃生舱(#21) | 🔄 方向已定,零落地 | 补强约束与自由代码之间最后一环 |
| chatdialog 拆分可拼装 UI | ✅ 已规划 | 降低集成门槛,「可定制」落地 |
